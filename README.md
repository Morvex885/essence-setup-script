# Essence

Rust-клиент `essence-rc` для настройки прокси-серверов по SSH и управления клиентскими конфигами на базе ядра [mihomo (Clash.Meta)](https://github.com/MetaCubeX/mihomo). Серверы описываются профилями нод в Remote Control и применяются на VPS неинтерактивным исполнителем; после настройки VPN работает без Remote Control.

Поддерживаемые протоколы: **VLESS Reality** (TCP, xHTTP, gRPC), **Hysteria2**, **AmneziaWG**, **WARP**, **Каскады нод**, **Telegram Web Proxy**.

|-----------|----------|-------------|
| **Серверная часть** | Профили и роли нод, рендер серверных файлов в Remote Control и исполнитель `node-agent/`, который применяет их на VPS | [docs/essence.md](docs/essence.md) |

## Возможности

### Серверная часть

- **Профили нод** — общее описание сервера (режим Reality, протоколы и порты, версия mihomo, сайт-заглушка, email Let's Encrypt, WARP, IPv6), на которое ссылаются ноды; на ноде — только домен, переопределения портов и сгенерированные ключи ([поля профиля](docs/essence.md#2-профиль-ноды))
- **Применение `node apply`** — проба ноды, план с подтверждением, расхождения с ручными правками, загрузка и отвязанный запуск исполнителя, опрос с переподключением после обрыва SSH, живой прогресс (процент, этап, текущее действие и время) в CLI, меню и веб-панели, транзакционная запись файлов с откатом; несколько нод применяются независимо ([подробнее](docs/essence.md#4-применение))
- **Установка mihomo** — бинарник под архитектуру сервера (amd64-v3/v2, armv7, arm64), systemd-сервис, UFW (свои правила без сброса; выключенный UFW включается с разрешённым SSH), BBR и sysctl-тюнинг
- **VLESS Reality** — XTLS-Reality с тремя транспортами:
  - **TCP** (flow `xtls-rprx-vision`) на 443
  - **xHTTP** через Reality или через nginx TLS
  - **gRPC** через Reality
  Два режима: **Self-Steal** (свой домен ноды + сайт-заглушка + acme.sh) или **SNI** (маскировка под чужой домен, нода без домена)
- **Hysteria2** — QUIC с опциональным `obfs salamander`
- **AmneziaWG 3.1** — WireGuard с DPI-обфускацией (Header Protection, content padding, randomized timings, Random Trailers, Disable Cookies); пиры изолированы друг от друга, трафик идёт через mihomo с запретом частных сетей и адреса ноды; ключи клиентов хранит Remote Control, родной `.conf` клиента — `client awg-config` (в веб-панели с QR-кодом)
- **WARP** — Cloudflare WARP как исходящий прокси через `wgcf`, аккаунт на каждой ноде, необязательный ключ WARP+ профиля и перерегистрация
- **Каскады** — входная нода + листенер + выход через другую ноду или внешний сервер (`vless://`, `hysteria2://`), свои учётные данные каскада у каждого клиента
- **Хост подписок** — роль ноды: HTTPS-публикация через nginx (`/sub/<token>`) на 443 или своём порту, ограничение запросов и автоочистка просроченных подписок
- **Telegram Web Proxy** — роль ноды: HTTPS/WebSocket-прокси с MTProxy как внутренним бэкендом, ссылка `tg://webproxy`, смена секрета, Спонсорский тег
- **Decoy-сайты** — рандомизированные HTML-шаблоны (Simple Web Templates, SNI Templates, Nothing Templates)
- **TLS-сертификаты** — общий acme.sh lifecycle для сайта ноды, подписок и Telegram: переиспользование пригодной пары, восстановление сохранённого архива без нового заказа, автоматическое продление через постоянный HTTP-01 route; [правила выдачи и освобождения](docs/essence.md#8-общий-lifecycle-сертификатов-acme)
- **IPv6** — поле профиля: по умолчанию, включить или выключить
- **Снятие** — снятие профиля и `node apply` (или `node delete --scope server`) удаляет всё установленное Essence; пакеты и acme.sh остаются

### Локальная часть (Remote Control)

- **Единое ядро команд** — вся логика в командах `сущность действие --флаги` → JSON `{ok,data|error}`. Ядро работает в фоновом демоне; терминальное меню, командная строка и веб-панель — его клиенты на одном протоколе ([remote-control/README.md](remote-control/README.md))
- **Веб-панель** — `essence-rc web run`: все разделы меню в браузере, терминал нод, вход по ссылке с кодом (действует, пока панель запущена; браузер помнит вход) или паролю запуска, автозапуск `essence-rc web install-service` ([docs/remote-control.md](docs/remote-control.md#веб-панель))
- **Удалённое управление** — `essence-rc --connect https://host:8377 …`: меню и команды на демоне другой машины с закреплением сертификата
- **Управление нодами** — добавление VPS с паролями под AES-256-GCM (ключ устройства), профиль, домен и порты ноды, состояние применения, переименование с каскадным апдейтом ссылок, теги, оболочка на ноде, удаление с опциональной очисткой сервера
- **Усиление защиты SSH** — генерация переносимого ed25519-ключа, копирование на сервер, отключение пароля, смена SSH-порта (49152-65535) и обновление firewall с проверкой результата
- **Клиенты** — создание с auto-generated `vless_uuid` + `hy2_password`, наследование нод от группы или кастомный список, смена группы с миграцией, переименование с миграцией директории
- **Группы** — шаблон на группу, маркеры `# --- GROUP ---` в YAML для per-group блоков, поддержка мульти-группы (`GROUP1/GROUP2`)
- **Подключения нод для групп** — подключения, которые даёт профиль ноды (VLESS/HY2/AWG/каскады), без обращения к ноде; цветной обзор покрытия, батч-назначение подключений группам, авточистка устаревших назначений
- **Генерация конфигов** — по группе или всем, per-client credentials injection из состояния RC без SSH, проверка дубликатов. Итог показывает готовых, пропущенных и ошибочных клиентов и ноды, ожидающие применения; публикация подписок — отдельное действие
- **Подписки** — хост подписок как роль ноды, публикация, отзыв и смена токенов, пакетное обновление, проверка HTTP 200 и очистка осиротевших файлов
- **HTTP-заголовки подписок** — наследование `default → group → client` с показом итогового значения и источника, безопасное quoting для nginx
- **Шаблоны** — создание на основе `default.yaml` или другого шаблона, редактор (`$VISUAL`/`$EDITOR`, nano, vi; в Windows — notepad) в меню, экспорт и импорт файлом, несколько шаблонов на проект
- **Обновления** — проверка версии и обновление бинарника командой `self update` (SHA-256 из `SHA256SUMS`) или из раздела «Настройки»
- **Пароль запуска** — Argon2id; для GitHub входит в логическое состояние и следует выбранному режиму шифрования
- **Каталог данных** — `~/.local/share/essence-remote-control` (Linux/Termux), `~/Library/Application Support/essence-remote-control` (macOS), `%APPDATA%\essence-remote-control` (Windows); переопределяется `ESSENCE_RC_DATA_DIR`
- **Командная строка** — `essence-rc <сущность> <действие> [--json]` без вопросов: источник, ноды, профили, каскады, группы, шаблоны, клиенты, подключения, генерация, подписки, Telegram и сам remote-control; опасные действия показывают план и выполняются только с `--yes` (необязательный `--plan-token` из плана гарантирует, что план не изменился); решения (`*_required`) возвращаются кодами с данными, секреты — через `--secrets-stdin` (`essence-rc help`)

Remote Control поддерживает переносимый источник состояния GitHub. При первом
выборе используется фиксированный приватный репозиторий
`<owner>/essence-remote-control-config`; имя и владельца нельзя случайно заменить.
Способ хранения выбирается один раз: зашифрованное хранилище `age` либо дерево
без шифрования. Ключ расшифровки можно сохранить на устройстве или экспортировать
во внешний файл восстановления. Офлайн-изменения сохраняются в локальной ветке
и получают статус «есть неотправленные изменения»; независимое изменение
локальной и удалённой веток останавливает синхронизацию без потери одной из версий.
Сгенерированные конфиги из `generated/` в GitHub не отправляются.
Пароли SSH переносятся между устройствами и заново шифруются локальным ключом.
В режиме `none` они и приватные SSH-ключи открыты читателям репозитория и остаются
в истории Git. Недоступный пароль не блокирует остальные ноды: проблемная нода
переносится без него и предлагает повторный ввод в карточке ноды (`n` → нода → `w`),
без изменения пароля на VPS или автоматического SSH. Ключи нод (Reality, AmneziaWG,
WARP, секреты Telegram) переносятся так же; ключ, который устройство не может
расшифровать, не удаляется из хранилища — при отправке сохраняется прежнее значение.

## Быстрый старт

Запустите Remote Control (`essence-rc`) — серверный исполнитель он загрузит на VPS сам при первом применении профиля ноды.

**Linux / macOS / Android (Termux) — установка:**
```bash
curl -fsSL https://raw.githubusercontent.com/Morvex885/essence-setup-script/main/install-essence-rc.sh | bash
essence-rc
```

Установщик определяет ОС и архитектуру (Linux x86_64/aarch64/armv7, macOS
Intel/Apple Silicon, Termux aarch64), скачивает `essence-rc-<target>.tar.gz` из
последнего релиза, сверяет SHA256 с `SHA256SUMS` и ставит бинарник в
`/usr/local/bin/essence-rc` (при необходимости через `sudo`); в Termux — в
`$PREFIX/bin` без root. Конкретная версия: `ESSENCE_RC_VERSION=v2.0.0`.

**Windows (x64 / ARM64):**

1. Скачайте из [последнего релиза](https://github.com/Morvex885/essence-setup-script/releases/latest)
   `essence-rc-x86_64-pc-windows-msvc.zip` (или `essence-rc-aarch64-pc-windows-msvc.zip`) и `SHA256SUMS`.
2. Сверьте хеш в PowerShell — он должен совпасть со строкой архива в `SHA256SUMS`
   (для ARM64 подставьте в обе команды `essence-rc-aarch64-pc-windows-msvc.zip`):
   ```powershell
   (Get-FileHash .\essence-rc-x86_64-pc-windows-msvc.zip -Algorithm SHA256).Hash.ToLower()
   Select-String essence-rc-x86_64-pc-windows-msvc.zip .\SHA256SUMS
   ```
3. Распакуйте `essence-rc.exe`, например, в `%USERPROFILE%\bin`. Если этого каталога
   нет в `PATH`, добавьте его один раз (PowerShell, затем откройте новое окно терминала):
   ```powershell
   New-Item -ItemType Directory -Force "$env:USERPROFILE\bin" | Out-Null
   [Environment]::SetEnvironmentVariable('Path', [Environment]::GetEnvironmentVariable('Path', 'User') + ";$env:USERPROFILE\bin", 'User')
   ```
   Затем запустите `essence-rc`. Без настройки `PATH` — по полному пути
   (PowerShell: `& "$env:USERPROFILE\bin\essence-rc.exe"`, cmd:
   `"%USERPROFILE%\bin\essence-rc.exe"`).

**Из исходников (для разработки):**
```bash
git clone https://github.com/Morvex885/essence-setup-script.git essence
cd essence/remote-control
cargo run -p essence-rc --release
```

Веб-панель: `essence-rc web run` — откроет браузер со ссылкой входа; Ctrl+C — остановить.

## Пошаговое руководство

### 1. Запустить Remote Control

Запустите `essence-rc` локально (см. «Быстрый старт» выше). При первом запуске будут автоматически созданы три группы: **ROUTER**, **PC**, **MOBILE**.

### 2. Создать профиль нод

`r` → `a`: имя, режим Reality (**Self-Steal** — у ноды свой домен; **SNI** — маскировка под чужой домен, нода без домена), источник сайта-заглушки или домен-маскировка, протоколы и порты (без порта — случайный), email Let's Encrypt (можно случайный), WARP, IPv6. Командная строка:

```bash
essence-rc profile add --name main --random-acme-email --reality self-steal --hysteria2 on --amneziawg on
```

Все поля и умолчания — в [docs/essence.md](docs/essence.md#2-профиль-ноды).

### 3. Добавить ноду с профилем и применить

`n` → `a` — IP ноды, SSH-порт, логин и способ авторизации (ключ или пароль), затем профиль и, если профиль требует, домен ноды (A-запись на IP сервера). Для усиления защиты сначала выбирается новый порт, затем показываются нода и последствия; один вопрос с ответом «нет» по умолчанию разрешает установку ключа и отключение пароля. В конце мастер предлагает применить профиль: RC покажет план и после подтверждения настроит сервер. То же из командной строки:

```bash
essence-rc node add --name de --ip 203.0.113.10 --auth key --tag DE --accept-new-host-key --profile main --domain de.example.com
# вход по паролю: --auth password, пароль — через stdin, не в argv
printf '{"password":"%s"}' "$SSH_PASSWORD" | essence-rc node add --name nl --ip 203.0.113.11 --auth password --tag NL --accept-new-host-key --profile main --secrets-stdin
essence-rc node apply --name de --yes
```

Состояние ноды видно в списке: «ожидает применения», «применяется…», «применено».

### 4. Группы

Три стандартные группы (ROUTER, PC, MOBILE) уже созданы. При необходимости добавьте свои: `g` → `a`. Каждой группе можно назначить свой шаблон конфига.

### 5. Создать клиентов

`c` → `a` → введите имя клиента и выберите группу. `vless_uuid`, `hy2_password` и ключи AmneziaWG генерируются автоматически.

### 6. Настроить подключения нод группам

`p` → выберите ноду. Подключения берутся из профиля ноды (`VLESS TCP`, `VLESS xHTTP`, `VLESS gRPC`, `Hysteria2`, `AWG` и каскады), к ноде RC не обращается. Назначьте их нужным группам (`conn set --name N --assign G=P`).

### 7. Применить изменения

Клиенты и подключения меняют пользователей листенеров на нодах, поэтому ноды снова ожидают применения: меню после изменения само предлагает применить их, из командной строки — `essence-rc node apply --pending`.

### 8. Сгенерировать конфиги

`f` → `a` (все клиенты) или `g` (по группе). Конфиги с per-client credentials появятся в директории `generated/`; итог перечисляет готовых, пропущенных и ошибочных клиентов и ноды, ожидающие применения.

### 9. (Необязательно) Хост подписок и публикация

`s` → «Хост подписок»: нода, домен (A-запись на ноду) и порт (443 по умолчанию), затем примените ноду (`subscription host --name N --domain D [--port P]`, `node apply --name N`). После этого опубликуйте токены клиентам (`subscription publish --name C` или `subscription publish-all`). Массовое обновление и обзор не печатают ссылки; данные конкретного клиента доступны через «Показать подписку». Клиенты получают конфиг по HTTPS:

```
https://<domain>[:<port>]/sub/<token>
```

## Требования

**Сервер:** Debian 12/13 или Ubuntu 22.04/24.04/26.04 с systemd, вход по SSH под root; домен с A-записью на IP сервера — для режима Self-Steal, хоста подписок и Telegram Web Proxy; x86_64 — для Telegram Web Proxy ([подробнее](docs/essence.md#9-требования))

**Локально:** только `essence-rc` (SSH встроен). Для источника GitHub — `git` и `gh`; для QR-кода подписки — `qrencode` (необязательно).

```
.
+-- common/
|   +-- common.sh                  # Вывод, cleanup при выходе, jq-обёртки

|   +-- apply.sh                   # Точка входа: этапы, транзакция, откат, статус операции
|   +-- steps/                     # base.sh, progress.sh, awg.sh, sub.sh, telegram.sh
+-- remote-control/                # Remote Control на Rust (Cargo workspace)
|   +-- core/                      # rc-core: модель, состояние, команды, SSH, GitHub, билдеры
|   |   +-- src/server/            # Рендер состояния ноды, node apply, встраивание исполнителя
|   |   +-- src/cli.rs             # Каталог команд и справка
|   |   +-- src/dispatch.rs        # Единый диспетчер, Session::mutate
|   |   +-- templates/default.yaml # Встроенный шаблон конфига
|   +-- client/                    # essence-rc-client: протокол v3, подключение к демону
|   +-- web/                       # essence-rc-web: веб-слушатель и панель (assets/)
|   +-- tui/                       # essence-rc-tui: терминальное меню (клиент демона)
|   +-- bin/                       # essence-rc: демон, CLI, меню, веб-панель, автозапуск
|   +-- README.md                  # Устройство и тесты
+-- install-essence-rc.sh          # Установщик essence-rc
+-- tests/                         # BATS-тесты серверной части (unit + fuzz)
+-- docs/                          # Документация
+-- VERSION                        # Текущая версия
```
