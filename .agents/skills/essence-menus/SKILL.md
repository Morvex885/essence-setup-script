# Essence menus

## Когда применять

Используйте этот skill для любого интерактивного меню, подменю, одиночного выбора, мультивыбора или общего UI-контракта в `common/`, `setup-essence/` (Bash) и в терминальном меню клиента `remote-control/tui/` (Rust, ratatui). Правила кадров, клавиш, цветов и подтверждений одинаковы для обоих; различаются только примитивы (раздел «Экраны essence-rc»). Не используйте для YAML-билдеров, серверной конфигурации без изменения UI, команд ядра (скилл `essence-commands`) и веб-интерфейсов.

## Порядок работы

1. Прочитайте `AGENTS.md`, соседний экран, вызывающие функции и все потребители изменяемого символа. Сохраните границы импорта: `common/` не импортирует продуктовые модули; `setup-essence/` импортирует только `common/`; крейт `remote-control/tui` не зависит от `rc-core`.
2. Источник Bash UI API — `common/common.sh`. Переиспользуйте `box_top`, `box_mid`, `box_bot`, `box_line`, `box_center`, `menu_item`, `menu_index_valid`, `menu_select`, `review_frame`, `startup_recovery_menu` и `toggle_select`. В Rust-меню — примитивы `remote-control/tui/src/ui.rs` (`View`, `Item`, `render`) и `app::Context` (`choose`, `select`, `secret`, `confirm`). Не создавайте локальные рисовальщики.
3. Обычный операционный сбой возвращает ненулевой код и оставляет вызывающее меню доступным. `error()` допустим только на настоящей границе процесса или для повреждения безопасности/невосстановимого состояния. Вызывающий экран обязан явно показать предупреждение и предложить повторить действие; автоматический retry запрещён.
4. Не показывайте секреты в обзорах и подтверждениях. Итог успешной установки/создания сохраняет автоматический вывод данных подключения; `--force` для Telegram не печатает ссылки. Чувствительные временные файлы создавайте с `umask 077` (в Rust — приватный `tempfile`-каталог 0700, файл 0600). В setup-essence для JSON используйте `jq_r`/`jq_w`; в `remote-control/tui/` нет ни файлов состояния, ни SSH — данные только из ответов команд ядра через serve.

## Шаблон меню

Каждый экран перерисовывает полный кадр в цикле. Геометрия — `BOX_W=68` codepoints; терминал должен быть шириной не менее 70. ANSI/OSC8, перенос строк, plain- и colored-текст передавайте готовому common renderer, не копируйте его локально.

- Пустая строка перед рамкой и перед prompt; заголовок через `box_center`; контекст и состояния (`GREEN` — готово/включено, `DIM` — отсутствует/выключено, `YELLOW` — требует внимания) внутри рамки. Во всех меню, selector, подтверждениях, read-only панелях, ошибочных и пустых состояниях шапка отделяется от содержимого одним `box_mid`. Шапка включает заголовок и существующие служебные строки версии/обновления. Непустой контекст отделяется от действий ещё одним `box_mid`. Без контекста заголовок отделяется сразу от действий одним разделителем; в read-only рамке разделитель перед отсутствующими действиями не рисуется. Пустая секция не рисуется, двух `box_mid` подряд не бывает. `box_center` остаётся примитивом центровки без автоматических разделителей; новые локальные рисовальщики/обёртки не вводятся.
- В корневых меню со списком нод или больше чем восемью действиями пункты группируются по смыслу в секции через дополнительные `box_mid`: список нод — отдельная секция, затем управление нодами, затем группы действий, последней — обслуживание с `0`. Пункты действий — по одному `menu_item key label [COLOR]`; буквенный UI-hotkey — ровно одна ASCII-буква, отображается в нижнем регистре, а обе формы (`w|W`) явно обрабатываются в одной `case`-ветке. `web`, `mtproto`, `restart`, `show` и другие словесные значения недопустимы как UI-hotkeys. Третий аргумент — имя переменной цвета (`GREEN`, `YELLOW`, `RED`, `CYAN`, `NC`), не ANSI-значение. `10` выравнивается renderer-ом как обычный ключ.
- Семантика цветов ключей: `CYAN` — переход, просмотр или выбор; `GREEN` — установка/создание; `YELLOW` — изменение, обновление или перезапуск; `RED` — удаление или отзыв секрета; `NC` — навигационный `0`. Цвет получает только ключ `key)`: `menu_item` сбрасывает цвет перед названием, название пункта не окрашивается (так же рендерит `ui::View` в Rust). В корневом меню разделы группируются по смыслу цветом главного действия раздела: создание сущностей (ноды, клиенты, группы, шаблоны) — `GREEN`, операции над конфигурацией и обслуживание (подключения, генерация, подписки, настройки) — `YELLOW`, просмотр и инфраструктура (AmneziaWG, Telegram Proxy, источник конфигурации) — `CYAN`.
- UI-hotkeys отделены от полной машинной CLI-грамматики: например, `telegram-proxy web install` остаётся `web install`, а не `w install`.
- Завершение — `box_bot`, затем безопасный `IFS= read`. CR удаляется из ответа. Перед dispatch проверяйте успешность `read`.
- Для меню раздела `0`/EOF возвращают `0`; Enter и неизвестный ввод печатают `warn "Неверный выбор."` и оставляют тот же экран. Каждый пункт имеет отдельную `case`-ветку; верхний и нижний регистр буквенных действий обрабатываются явно.
- Подменю остаётся после действия, ошибки или отказа подтверждения и имеет `0) Назад`; исчезновение контекста возвращает к ближайшему существующему родителю. Selector для уже начатой операции имеет `0) Отмена` и возвращает `1` на `0`/EOF. Параметры, подтверждения и машинный CLI не превращайте в меню.
- Read-only обзор не изображает псевдо-hotkeys и не выводит секреты автоматически. Опасное действие сначала показывает операцию, последствия и все targets без секретов, затем ровно один локальный `confirm_yn ... N`; Enter/N/EOF не запускают действие.
- `--force` в UI-flow допустим только после этого подтверждения. Наличие `--force` само по себе не делает install/update опасным; машинные API не получают интерактивных prompts, а прямые серверные handlers сохраняют свои подтверждения. В `remote-control/tui/` `--force` передаётся только вместе с планом команды (`confirm::run_confirmed`), без собственного вопроса.
- Ошибка → warning, существующий cleanup/rollback, ненулевой return до menu boundary; не используйте fatal `error`, `exit`, `set -e` или автоматический retry в меню.

Пример формы:

```bash
while true; do
    echo ""
    box_top
    box_center "Раздел"
    box_mid
    box_line " Состояние: нет" " ${DIM}Состояние: нет${NC}"
    box_mid
    menu_item 1 "Установить" GREEN
    menu_item 0 "Назад" NC
    box_bot
    echo ""
    if ! IFS= read -rp "  Выберите действие: " choice; then
        return 0
    fi
    choice="${choice%$'\r'}"
    case "$choice" in
        1) operation || warn "Операция завершилась ошибкой. Повторите действие из меню." ;;
        0) return 0 ;;
        *) warn "Неверный выбор." ;;
    esac
done
```

Для Hysteria2 используйте именно такой контракт: `hy2_menu` — цикл с framed status, `1` install, `2` remove, `0`/EOF назад; `install_hy2` после `gen_free_port` проверяет код возврата, показывает framed selector для outbound/DIRECT, а любой сбой возвращает в `hy2_menu`, не завершает entrypoint. Серверные root/tag/component подменю Telegram находятся в `setup-essence/modules/telegram-proxy.sh`; essence-rc открывает их по SSH (`telegram menu`), команды ядра `telegram` — в `remote-control/core/src/telegram/`, экраны Telegram — в `remote-control/tui/src/nodes.rs`.

## Выбор из списка и мультивыбор

Одиночный список возвращает результат только после валидной проверки индекса. Сначала очистите глобальный результат, затем прочитайте локальный `choice`; отмена/EOF оставляют пустой результат и возвращают `1`. Пустой список рисуется отдельным full-frame состоянием: `box_top` → заголовок → `box_mid` → DIM-строка ` Нет нод для выбора` (plain первым аргументом `box_line`) → `box_mid` → `0) Отмена` → `box_bot` → пустая строка; он не читает input, не вызывает `node_load` и не делает SSH.

Для обычного списка используйте `menu_select title prompt items…` напрямую, без `$(…)`: результат — `MENU_SELECT_INDEX`. `MENU_SELECT_CONTEXT` и `MENU_SELECT_EMPTY` задаются перед вызовом и очищаются при возврате. Предпросмотр опасного действия в setup-essence — `review_frame title lines…`, затем одно `confirm_yn … N`; в `remote-control/tui/` то же делает `confirm::run_confirmed` по плану из ответа команды. Выбор в Rust-меню — `Context::select` (пустой список — full frame без чтения ввода).

Перед арифметикой и индексированием проверяйте номер через `menu_index_valid`; `0`, ведущие нули, знаки, пробелы и выражения недействительны. Для выбора ноды номер, имя и `IP:port` показывайте одним label через `menu_item index "name  IP:port"`; отдельная дочерняя строка адреса не нужна. Сохраняйте исходный порядок. Контекстное меню ноды использует текущий индекс без повторного selector/input.

`toggle_select` получает элементы только через глобалы `TOGGLE_SELECT_ITEMS` и `TOGGLE_SELECT_FLAGS`. Перед вызовом очистите результат и задайте оба массива; после вызова сохраните flags и очистите оба global-массива на любом исходе. Проверяйте rc до составления targets. Enter подтверждает текущий набор и возвращает `0`; `0`/EOF отменяют и возвращают `1`; частичные flags при отмене не передаются remote actions. Не запускайте toggle в command substitution: это ломает изменение flags. Для опасных действий (удаление, отключение, пакетные операции над нодами и клиентами) элементы изначально **не отмечены**: случайный Enter ничего не выбирает; предварительные отметки допустимы только там, где они отражают текущее состояние (собственные ноды клиента, назначенные подключения).

Preflight, объединённое согласие и замороженный план удалённых Telegram-операций — часть команд ядра `telegram` (см. скилл `essence-commands`); экран только показывает план через `confirm::run_confirmed` и таблицу результатов.

## Экраны essence-rc (`remote-control/tui/`)

Терминальное меню клиента — библиотека `essence-rc-tui`, запускается в процессе `essence-rc` без аргументов и общается с ядром только через приватный дочерний `essence-rc serve --inner` (JSONL v2). Экраны: `system.rs` — вход (session gate, первый запуск, восстановление), сводка, настройки; `source.rs` — источник и мастер GitHub; `nodes.rs` — ноды, карточка, добавление, усиление SSH, SSH-настройка, псевдонимы, подключения, AmneziaWG, Telegram; `clients.rs` — клиенты, группы, шаблоны и редактор, генерация, подписки. Каркас — `app.rs` (стек экранов, сигналы, приостановка терминала), `ui.rs` (кадры), `confirm.rs` (подтверждение и коды решений), `serve.rs` (клиент протокола). Таблица экранов (раздел → команды) — `docs/remote-control.md`, раздел «Главное меню».

- **Только слой экранов.** Экран получает `Context` и обращается к ядру только через `ServeClient` (`ctx.call`/`ctx.request`); импорт `rc_core` запрещён (`remote-control/tui/tests/boundary.rs`). Данные читаются командой в начале каждой итерации цикла; расчётов состояния в экране нет.
- **Опасное действие** — `confirm::run_confirmed(ctx, title, question, argv, secrets)`: команда без `--yes` отвечает `confirmation_required` с `plan` и `plan_token`, экран показывает review-кадр, задаёт один y/N (по умолчанию N) и повторяет команду с `--yes --plan-token`; `plan_changed` показывается заново не более двух раз. Своих вопросов «вы уверены?» поверх плана нет; `--force` — только внутри такого вызова.
- **Решения и коды.** Коды `_required` с extra экран превращает в один вопрос на код и повторяет команду с флагом (`confirm::decision_flag`/`set_flag` — единственное место соответствия код → флаг) или секретом; коды ноды (`missing_secret`, `host_key_changed`, `needs_setup`) решает `nodes::handle_node_codes`. Текст ошибки ядра показывает один раз `Context::request` (кроме планов и `_required`) — экран его не повторяет.
- **Секреты** вводятся скрытно (`ctx.secret`), передаются только полем `secrets` запроса (`serve::Secrets`, `Zeroizing`) и очищаются на любом исходе; в argv, кадры и журнал они не попадают.
- **Выбор.** `ctx.select` для одиночного списка; мультивыбор — по умолчанию без отметок, предварительные отметки только как отражение текущего состояния.
- **Стрелки.** `TerminalUi` дополняет ключи подсветкой пункта (`app::Picker`): ↑/↓ — по кругу, Enter/→ — выбрать, Esc/← — ввод `0`. Экран только задаёт `view.mode`: `Menu` по умолчанию (позиция по заголовку держится только для возврата из подменю; `0`/Esc её сбрасывает), `Select` — одиночный выбор, `Toggle` — мультивыбор (Пробел переключает, Enter сохраняет), `Root` — кадр с `0) Выход` (Esc/← не действуют). Ответ экрана — та же строка ключа, разбор не меняется.
- **Терминальные команды.** `node shell`/`telegram menu` — `ctx.interactive(argv)`: меню приостанавливается, команду выполняет serve-потомок на общем терминале. Внешний редактор шаблонов — `ctx.ui.suspended(&mut Command)` (`$VISUAL`/`$EDITOR`/nano/vi, в Windows notepad) на приватном временном файле с проверкой «без изменений».
- **Исчезновение объекта** (`not_found` при чтении карточки) возвращает к списку. Ctrl+C в меню закрывает сессию (выход 130), во время команды он её не прерывает.
- **Тесты экранов** — `#[cfg(test)]` модули `remote-control/tui/src/*.rs` на `ScriptedClient` (точный argv каждого запроса, имена секретов) и `ScriptedUi`/TestBackend (кадры, разделители, цвета ключей); сквозные сценарии настоящего бинарника в PTY — `remote-control/bin/tests/tui_e2e.rs` (включая обход разделов против настоящего ядра без `usage`). Проверяется поведение, не снимки русских формулировок.

## Проверка

- Для каждого изменённого `.sh`: отдельный `/bin/bash -n file`; для Rust — `cd remote-control && cargo test --workspace --locked`.
- Для Bash UI: smoke-прогон реального entrypoint или throwaway-сценария с вводом valid/invalid/Enter/0/EOF и проверкой возврата. После `source` всего модуля вызывайте активное имя меню; извлечение первого совпадения функции недопустимо. Общие примитивы `common/common.sh` покрывает `tests/unit/menu_ui.bats`.
- Проверяйте фактический полный кадр: вся шапка → разделитель → контекст → разделитель → действия. Отдельно покрывайте контекстные и бесконтекстные ветки, пустые/ошибочные состояния, длинные/многострочные заголовки и все рамки-потребители изменённого shared helper. Проверяйте отсутствие соседних разделителей и пустых секций по выводу, а не только наличие `box_mid` в source.
- Для каждого меню проверяйте обе формы каждой буквы, отказ от старых словесных UI-hotkeys и визуально короткую ноду одной строкой: `1) nuxt-de  144.31.96.60:22`.
- Для меню проверяйте сохранение текущего раздела после ошибки, отмену selector, локальное подтверждение до VERSION/upload/forced remote action и ровно один `--force`. Read-only SSH-preflight до вопроса допустим; отказ/EOF не допускает загрузки или SSH-мутаций. Проверяйте targets и отсутствие секретов, а не snapshots русских надписей/цветов.
- Канонический skill — этот файл в `.agents/skills/essence-menus`. Если `.claude/skills/essence-menus` присутствует, он должен быть ссылкой на канонический каталог, а не вторым набором правил; отсутствие Claude-конфигурации не требует её создания.
- Не печатайте пароли, токены, приватные ключи или расшифрованные credentials в обзорах, диагностике или подтверждениях. Данные подключения допустимы только по явному запросу и в предусмотренном итоговом выводе успешной установки/создания. Не добавляйте `set -e` в существующие entrypoints.
