# Essence menus

## Когда применять

Используйте этот skill для любого интерактивного меню, подменю, одиночного выбора, мультивыбора или общего UI-контракта в `common/`, `setup-essence/` и `remote-control/`. Не используйте для YAML-билдеров, серверной конфигурации без изменения UI и веб-интерфейсов.

## Порядок работы

1. Прочитайте `AGENTS.md`, соседний экран, вызывающие функции и все потребители изменяемого символа. Сохраните границы импорта: `common/` не импортирует продуктовые модули; `setup-essence/` и `remote-control/` импортируют только `common/`, не друг друга.
2. Источник UI API — `common/common.sh`. Переиспользуйте `box_top`, `box_mid`, `box_bot`, `box_line`, `box_center`, `menu_item`, `menu_index_valid`, `menu_select`, `review_frame`, `startup_recovery_menu` и `toggle_select`; в remote-control — `node_pick`. Не создавайте локальные рисовальщики.
3. Обычный операционный сбой возвращает ненулевой код и оставляет вызывающее меню доступным. `error()` допустим только на настоящей границе процесса или для повреждения безопасности/невосстановимого состояния. Вызывающий экран обязан явно показать предупреждение и предложить повторить действие; автоматический retry запрещён.
4. Не показывайте секреты в обзорах и подтверждениях. Итог успешной установки/создания сохраняет автоматический вывод данных подключения; `--force` для Telegram не печатает ссылки. Чувствительные временные файлы создавайте с `umask 077`. Для JSON используйте `jq_r`/`jq_w`; для SSH — штатные `ssh_run`/`scp_run`.

## Шаблон меню

Каждый экран перерисовывает полный кадр в цикле. Геометрия — `BOX_W=68` codepoints; терминал должен быть шириной не менее 70. ANSI/OSC8, перенос строк, plain- и colored-текст передавайте готовому common renderer, не копируйте его локально.

- Пустая строка перед рамкой и перед prompt; заголовок через `box_center`; контекст и состояния (`GREEN` — готово/включено, `DIM` — отсутствует/выключено, `YELLOW` — требует внимания) внутри рамки. Во всех меню, selector, подтверждениях, read-only панелях, ошибочных и пустых состояниях шапка отделяется от содержимого одним `box_mid`. Шапка включает заголовок и существующие служебные строки версии/обновления. Непустой контекст отделяется от действий ещё одним `box_mid`. Без контекста заголовок отделяется сразу от действий одним разделителем; в read-only рамке разделитель перед отсутствующими действиями не рисуется. Пустая секция не рисуется, двух `box_mid` подряд не бывает. `box_center` остаётся примитивом центровки без автоматических разделителей; новые локальные рисовальщики/обёртки не вводятся.
- В корневых меню со списком нод или больше чем восемью действиями пункты группируются по смыслу в секции через дополнительные `box_mid`: список нод — отдельная секция, затем управление нодами, затем группы действий, последней — обслуживание с `0`. Пункты действий — по одному `menu_item key label [COLOR]`; буквенный UI-hotkey — ровно одна ASCII-буква, отображается в нижнем регистре, а обе формы (`w|W`) явно обрабатываются в одной `case`-ветке. `web`, `mtproto`, `restart`, `show` и другие словесные значения недопустимы как UI-hotkeys. Третий аргумент — имя переменной цвета (`GREEN`, `YELLOW`, `RED`, `CYAN`, `NC`), не ANSI-значение. `10` выравнивается renderer-ом как обычный ключ.
- Семантика цветов ключей: `CYAN` — переход, просмотр или выбор; `GREEN` — установка/создание; `YELLOW` — изменение, обновление или перезапуск; `RED` — удаление или отзыв секрета; `NC` — навигационный `0`.
- UI-hotkeys отделены от полной машинной CLI-грамматики: например, `telegram-proxy web install` остаётся `web install`, а не `w install`.
- Завершение — `box_bot`, затем безопасный `IFS= read`. CR удаляется из ответа. Перед dispatch проверяйте успешность `read`.
- Для меню раздела `0`/EOF возвращают `0`; Enter и неизвестный ввод печатают `warn "Неверный выбор."` и оставляют тот же экран. Каждый пункт имеет отдельную `case`-ветку; верхний и нижний регистр буквенных действий обрабатываются явно.
- Подменю остаётся после действия, ошибки или отказа подтверждения и имеет `0) Назад`; исчезновение контекста возвращает к ближайшему существующему родителю. Selector для уже начатой операции имеет `0) Отмена` и возвращает `1` на `0`/EOF. Параметры, подтверждения и машинный CLI не превращайте в меню.
- Read-only обзор не изображает псевдо-hotkeys и не выводит секреты автоматически. Опасное действие сначала показывает операцию, последствия и все targets без секретов, затем ровно один локальный `confirm_yn ... N`; Enter/N/EOF не запускают действие.
- `--force` в UI-flow допустим только после этого подтверждения. Наличие `--force` само по себе не делает install/update опасным; машинные API не получают интерактивных prompts, а прямые серверные handlers сохраняют свои подтверждения.
- Ошибка → warning, существующий cleanup/rollback, ненулевой return до menu boundary; не используйте fatal `error`, `exit`, `set -e` или автоматический retry в меню. `state_action` оборачивает одну мутацию, не menu-loop.

Пример формы:

```bash
while true; do
    echo ""
    box_top
    box_center "Раздел"
    box_mid
    box_line " Состояние: нет" " ${DIM}Состояние: нет${NC}"
    box_mid
    menu_item 1 "Установить" GREEN
    menu_item 0 "Назад" NC
    box_bot
    echo ""
    if ! IFS= read -rp "  Выберите действие: " choice; then
        return 0
    fi
    choice="${choice%$'\r'}"
    case "$choice" in
        1) operation || warn "Операция завершилась ошибкой. Повторите действие из меню." ;;
        0) return 0 ;;
        *) warn "Неверный выбор." ;;
    esac
done
```

Для Hysteria2 используйте именно такой контракт: `hy2_menu` — цикл с framed status, `1` install, `2` remove, `0`/EOF назад; `install_hy2` после `gen_free_port` проверяет код возврата, показывает framed selector для outbound/DIRECT, а любой сбой возвращает в `hy2_menu`, не завершает entrypoint. Серверные root/tag/component подменю Telegram находятся в `setup-essence/modules/telegram-proxy.sh`; remote-control открывает их по SSH, а `remote-control/modules/telegram-proxy.sh` содержит только выбор ноды и массовые операции.
## Выбор из списка и мультивыбор

Одиночный список возвращает результат только после валидной проверки индекса. Сначала очистите глобальный результат, затем прочитайте локальный `choice`; отмена/EOF оставляют пустой результат и возвращают `1`. Пустой список рисуется отдельным full-frame состоянием: `box_top` → заголовок → `box_mid` → DIM-строка ` Нет нод для выбора` (plain первым аргументом `box_line`) → `box_mid` → `0) Отмена` → `box_bot` → пустая строка; он не читает input, не вызывает `node_load` и не делает SSH.

Для обычного списка используйте `menu_select title prompt items…` напрямую, без `$(…)`: результат — `MENU_SELECT_INDEX`. `MENU_SELECT_CONTEXT` и `MENU_SELECT_EMPTY` задаются перед вызовом и очищаются при возврате. `node_pick title` публикует `NODE_PICK_INDEX`, но не загружает ноду. Предпросмотр опасного действия — `review_frame title lines…`, затем одно `confirm_yn … N`.

Перед арифметикой и индексированием проверяйте номер через `menu_index_valid`; `0`, ведущие нули, знаки, пробелы и выражения недействительны. Для node picker номер, имя и `IP:port` показывайте одним label через `menu_item index "name  IP:port"`; отдельная дочерняя строка адреса не нужна. Сохраняйте исходный порядок. Контекстное меню ноды использует текущий индекс без повторного selector/input.

`toggle_select` получает элементы только через глобалы `TOGGLE_SELECT_ITEMS` и `TOGGLE_SELECT_FLAGS`. Перед вызовом очистите результат и задайте оба массива; после вызова сохраните flags и очистите оба global-массива на любом исходе. Проверяйте rc до составления targets. Enter подтверждает текущий набор и возвращает `0`; `0`/EOF отменяют и возвращают `1`; частичные flags при отмене не передаются remote actions. Не запускайте toggle в command substitution: это ломает изменение flags.

Для удалённых Telegram-операций всегда выполняйте read-only preflight всех нод. Разрушительное действие или хотя бы один upload требует единственного объединённого диалога после preflight; обновление IP и перезапуски без upload вопросов не задают. До требуемого согласия запрещены серверные записи и действия, но разрешена проверка файлов по SSH. Недоступную ноду исключите и сохраните результат «ошибка»; доступные targets продолжают обработку. Отказ/EOF отменяет всю группу и очищает снимки credentials. Workers используют замороженные параметры нод, только разрешённые uploads и точно согласованный VERSION; интерактивных вопросов не задают. Изменившийся после согласия локальный комплект блокирует запуск без автоматической перезаписи или второго вопроса.

Одиночный вход `telegram-proxy menu` по SSH использует тот же preflight и подготовленный план на одну ноду. Не вызывайте `ensure_remote_scripts_current` для этого входа: его автоматическая загрузка missing/older скриптов обходит согласие. Если upload не нужен, открывайте серверное меню с TTY без вопроса; если нужен — только после согласия, проверки SHA-256 и точного опубликованного VERSION. Отказ/Enter/EOF возвращает в локальный контекст без upload и без открытия SSH-меню. Параметры соединения берите из снимка, снимки credentials очищайте на любом исходе.

## Проверка

- Для каждого изменённого `.sh`: отдельный `/bin/bash -n file`.
- Для UI: smoke-прогон реального entrypoint или throwaway-сценария с вводом valid/invalid/Enter/0/EOF и проверкой возврата. После `source` всего модуля вызывайте активное имя меню; извлечение первого совпадения функции недопустимо.
- Проверяйте фактический полный кадр: вся шапка → разделитель → контекст → разделитель → действия. Отдельно покрывайте контекстные и бесконтекстные ветки, пустые/ошибочные состояния, длинные/многострочные заголовки и все рамки-потребители изменённого shared helper. Проверяйте отсутствие соседних разделителей и пустых секций по выводу, а не только наличие `box_mid` в source.
- Для каждого меню проверяйте обе формы каждой буквы, отказ от старых словесных UI-hotkeys и визуально короткую ноду одной строкой: `1) nuxt-de  144.31.96.60:22`.
- Для меню проверяйте сохранение текущего раздела после ошибки, отмену selector, локальное подтверждение до VERSION/upload/forced remote action и ровно один `--force`. Read-only SSH-preflight до вопроса допустим; отказ/EOF не допускает загрузки или SSH-мутаций. Проверяйте targets и отсутствие секретов, а не snapshots русских надписей/цветов.
- Канонический skill — этот файл в `.agents/skills/essence-menus`. Если `.claude/skills/essence-menus` присутствует, он должен быть ссылкой на канонический каталог, а не вторым набором правил; отсутствие Claude-конфигурации не требует её создания.
- Не печатайте пароли, токены, приватные ключи или расшифрованные credentials в обзорах, диагностике или подтверждениях. Данные подключения допустимы только по явному запросу и в предусмотренном итоговом выводе успешной установки/создания. Не добавляйте `set -e` в существующие entrypoints.
